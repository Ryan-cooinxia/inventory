# 2026-07-01 OZON 官方 Excel 模板发布通道

## 背景

当前系统通过直接调用 OZON API (`/v3/product/import`) 发布商品，但这是异步任务，经常出现"任务已提交但后台无商品"的情况。新增"官方 Excel 模板发布通道"作为稳定备选——用户可以从草稿生成填充好的 OZON 官方 Excel 模板，手动上传到 OZON 后台发布。

## 新增功能

### 1. 模板管理
- **上传**: 用户上传 OZON 官方 Excel 模板（.xlsx/.xlsm），系统自动解析表头结构、必填列（`*` 标记）、数据验证规则
- **绑定**: 模板绑定到 `dcid + type_id` 对，同对上传新模板时旧模板自动标记为 `outdated`
- **Schema Hash**: 基于表头名排序计算 SHA256，追踪模板结构版本
- **页面**: `/ozon/excel-templates` 模板管理页，支持上传、列表查看、删除

### 2. Excel 模板生成
- **草稿 → Excel**: 在刊登草稿审核页点击「生成 OZON 模板 Excel」
- **复制原模板**: 保留原模板的所有 Sheet、数据验证、格式
- **自动填充**: 从 `data_start_row`（默认第 5 行）开始填入草稿数据
- **多 SKU**: 每个 SKU 一行
- **字段映射**:
  - 货号* ← sku.offer_id
  - 商品名称 ← draft.title_ru
  - 价格* ← pricing_json.listing_price
  - 主图链接* ← media_json 外链（必须是 http/https 开头）
  - 品牌* ← attributes_json 品牌属性
  - 型号名称* ← source sku/model
  - 类型* ← draft.type_name_cn
  - 简介 ← draft.description_ru
  - JSON富内容 ← draft.rich_content_json

### 3. 导出追踪
- 每次导出自动记录（OzonTemplateExportJob）
- 导出后页面显示下载链接 + 结果标记按钮
- 标记状态: 已发布 / 已验证 / 有错误 / 需修复

### 4. 模板状态指示
- **适配工作台**: 选 type 后自动检测模板是否就绪，显示徽章 + 快捷入口
- **草稿列表**: 每行显示 📊可导出 / 📊无模板
- **草稿审核页**: 有 type_id 时自动显示模板导出按钮组

## 关键约束

1. **图片必须外链**: 生成前检查主图 URL 是否以 http/https 开头，本地路径拒绝生成并提示
2. **模板版本追踪**: schema_hash 自动检测结构变化，旧模板 outdated
3. **只复制不重建**: Excel 生成时 copy 原模板 workbook，保留所有 Sheet/验证/格式

## 2026-07-01 后续优化：模板上传自动识别 dcid/type_id

### 问题
上传模板时必须手动填写 dcid 和 type_id，用户不知道这些 ID 从哪来，体验差。

### 解决方案
1. **去掉必填限制** — dcid/type_id 改为可选，上传后通过 `schema_hash` 自动匹配已有模板
2. **自动识别** — 计算上传文件的表头结构哈希，和库里已有模板比对，命中则自动复用 dcid/type_id
3. **未绑定模板** — 识别失败且用户未手动填写时，存为"未绑定"（dcid='', type_id=''），可从适配工作台跳转重传绑定
4. **智能回退** — 草稿生成 Excel 时，精确匹配失败则回退到未绑定模板

### 影响文件
- `blueprints/ozon.py` — 上传接口去掉必填校验，新增 schema_hash 自动匹配，生成 Excel 时回退未绑定模板
- `templates/ozon/excel_templates.html` — 去掉 required 属性，显示自动识别结果和未绑定提示

## 2026-07-01 核心 Bug 修复：Excel 生成数据错行 + 类型绑定错误

### 问题
1. data_start_row 被自动检测为第 3 行（说明行），数据写错位置
2. 模板原始示例值未清空，写入逻辑跳过已有值的单元格
3. 自动识别把取景器模板误判为 type_id=91740（相机配件）
4. `_extract_attribute_value()` 只匹配 `attribute_name`，草稿属性缺少此字段
5. 同 dcid 回退太危险，允许用不对应的模板生成

### 修复
1. **固定 data_start_row=5** — OZON 模板固定第 2 行表头、第 5 行数据，不再自动检测
2. **写入前清空数据区** — 第 5 行起全部清空，保留公式和样式，强制覆盖写入
3. **类型优先识别** — 上传时读第 5 行「类型*」列值 → 查 OzonCategoryType 精确匹配（优先级高于属性名匹配）
4. **属性提取重写** — 改用 attribute_id 查 OzonCategoryAttribute + OzonAttributeValue，字典值取俄语原值
5. **去掉同 dcid 回退** — 生成 Excel 仅精确匹配 dcid+type_id，避免用错模板
6. **生成后校验** — 保存后重新打开检查货号/标题/价格/主图/品牌/型号/类型是否为空，类型是否含中文
7. **修复已有数据** — 模板 id=1 重新绑定到 970960410/Видоискатель，data_start_row 修正为 5

### 影响文件
- `services/ozon_template_excel.py` — 重写 inspect/generate/_extract_attribute_value/build_field_mapping
- `blueprints/ozon.py` — 去掉同 dcid 回退，type_hint 优先识别，适配新返回签名
- `templates/ozon/listing_review.html` — 校验错误时展示缺失字段
- 数据库修复：OzonExcelTemplate id=1 → type_id=970960410
