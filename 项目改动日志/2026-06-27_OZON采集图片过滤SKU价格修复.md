# 2026-06-27 OZON 采集图片过滤、SKU 与价格修复

## 背景

重新启动后，OZON 页面已经可以采集详情图，但出现三个新问题：

1. 详情图采集范围过宽，混入评论图、推荐商品图、平台图标、OZON Bank 等非商品图片。
2. SKU 仍无法识别，适配工作台显示 `源 SKU(0)`。
3. 页面参考价格无法进入系统。

## 根因

- 插件端旧逻辑把 `[class*="widget"]`、全页面 `img` 等作为兜底采集来源，导致评论区、推荐区、平台组件图标被当成详情图。
- 图片角色过度依赖 URL 和粗略选择器，没有强制区分 `main_gallery / sku_panel / detail_content` 三类白名单区域。
- 后端对 OZON 来源图片统一标记为 `needs_review`，导致即使前置分类结果是 `rejected`，也仍然保存到待审核图库。
- SKU 识别只扫少量按钮选择器，没有默认 SKU 兜底。
- 插件虽然可以扩展返回价格信息，但提交 payload 与后端 raw_json 没有完整接住 `pricing / price_candidates`。

## 本次改动

### 1. 浏览器插件 `browser-extension/content.js`

- 新增 OZON 专用采集函数 `extractOzonProduct()` v2.3。
- 图片采集改为白名单区域：
  - 主图：商品图库 / 轮播 / gallery 区域。
  - SKU 图：规格 / variant / aspect / sku 区域。
  - 详情图：description / rich content / 详情内容区域。
- 增加黑名单过滤：
  - 评论、问答、买家秀、推荐商品、相似商品、店铺/卖家区、导航、浮层、广告、银行/支付/分期、平台图标等。
- 不再使用“全页面图片兜底为详情图”的策略。
- SKU 识别增加：
  - DOM 规格区识别。
  - 页面状态 JSON 保守识别。
  - 标题兜底生成默认规格。
- 价格识别增加：
  - meta price。
  - 价格组件 DOM。
  - 页面状态 JSON 中的 price/finalPrice/salePrice 等字段。
- `extract()` 和提交 payload 增加：
  - `videos`
  - `pricing`
  - `price_candidates`

### 2. 后端接口 `blueprints/ozon.py`

- `/ozon/api/sources/add` 接收并保存 `pricing / price_candidates` 到 raw_json。
- OZON 来源如果没有 SKU，则自动创建 1 个默认规格，避免适配工作台断流。
- OZON 参考价格会写入默认 SKU 的价格字段，但 `price_manual_confirmed` 保持 false，表示发布前仍需人工确认。
- OZON 来源中被分类为 `rejected` 的图片不再保存到待审核图库。

### 3. 图片分类服务 `services/ozon_collector.py`

- 增加后端可识别的拒绝区域：
  - `review`
  - `recommendation`
  - `rejected`

## 预期效果

- 源图片图库中不再大量混入评论图、推荐商品图、平台图标。
- 若 OZON 页面没有明显规格按钮，系统至少生成 1 个默认 SKU。
- 能采集到 OZON 页面参考售价，并在后续人工确认前保持未确认状态。
- 详情图数量会减少，但质量更高，优先保留真正的商品详情内容。

## 已验证

- `node --check browser-extension/content.js` 通过。
- 使用 Codex 内置 Python 执行：
  - `python -m py_compile blueprints/ozon.py services/ozon_collector.py`
  - 通过。

## 后续验证

1. 在 Chrome 扩展管理页重新加载插件。
2. 刷新 OZON 商品页。
3. 点击“采集此商品”。
4. 检查适配工作台：
   - `源 SKU` 不应为 0。
   - 源图片图库中评论图、推荐商品图、平台图标应明显减少。
   - 价格应进入 SKU 价格输入框或 raw_json 的 pricing 字段。
5. 如发现详情图过少，再针对具体 OZON 页面补充新的详情区白名单选择器。
