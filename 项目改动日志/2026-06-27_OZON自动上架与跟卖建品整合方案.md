# OZON 自动上架与跟卖建品整合方案

更新时间：2026-06-27  
文档位置：`G:\inventory\项目改动日志\2026-06-27_OZON自动上架与跟卖建品整合方案.md`

## 1. 项目目标

本阶段要做的不是单纯“自动发布商品”，而是建立一套面向 OZON 的商品上架工作流：

```text
采集商品资料
→ 确认采集成果
→ 建立商品事实档案
→ 分析商品是否值得做
→ 生成主图 / SKU 图 / 详情图
→ 生成 Listing 草稿
→ 审核草稿
→ 提交 OZON 发布
→ 根据结果复盘优化
```

系统最终应具备两类上架入口：

1. 货源建品  
   从 1688、淘宝、天猫、拼多多、手动资料等来源采集商品，整理后上架 OZON。

2. OZON 参考建品 / 跟卖建品  
   像店小秘、妙手 ERP 一样，用户粘贴 OZON 商品链接，系统采集已有 Listing 信息，快速匹配我方商品或货源，生成可审核的我方 Listing 草稿。

## 2. 核心原则

### 2.1 不做无脑复制

OZON 链接采集来的内容默认只作为参考，不应直接原样发布。

默认可参考：

- 类目
- type
- 属性结构
- SKU 结构
- 标题关键词
- 价格区间
- 图片排版逻辑
- 卖点表达方向

默认需要替换或重新生成：

- 竞品主图
- SKU 图
- 详情图
- 竞品原文描述
- 竞品品牌词
- 店铺专属素材
- 商标 / Logo / 认证图

### 2.2 先确认事实，再生成内容

AI 生图、标题、详情页、OZON 属性、发布请求都必须基于已确认的商品事实。

如果商品事实不准，后续所有环节都会返工。

### 2.3 页面职责要拆清楚

商品适配工作台负责“商品是什么、怎么适配”。  
刊登草稿审核页负责“最终能不能发布”。  
图片方案页负责“图片是否能吸引点击和促成下单”。  
发布任务页负责“提交 OZON 和记录结果”。

E. 生成层

F. 审核发布层
   草稿审核
   发布前校验
   提交 OZON

G. 结果复盘
   成功回写
   失败修正
   数据复盘

## 5. OZON 商品链接采集与跟卖建品

### 5.1 功能定位

该功能类似店小秘、妙手 ERP 的链接采集上架能力：

```text
粘贴 OZON 商品链接
→ 采集原 Listing 信息
→ 解析商品结构
→ 匹配我方商品 / 货源
→ 判断是否适合跟卖
→ 生成我方 Listing 草稿
→ 替换图片 / 文案 / 价格
→ 审核后发布
```

建议功能名称：

```text
OZON 链接建品
```

或：

```text
OZON 参考建品 / 跟卖建品
```

### 5.2 第一阶段采集字段

OZON 单链接采集至少提取：

- 商品 URL
- OZON 商品 ID
- 俄语标题
- 中文标题，如果 AI 可翻译
- 店铺 / 卖家
- 品牌
- 类目路径
- description_category_id，如果可获得
- type_id，如果可获得
- 当前售价
- 原价
- SKU 列表
- SKU 价格
- SKU 图片
- 主图
- 详情图
- 商品描述
- 参数 / 属性
- 评分
- 评论数量
- raw_text
- raw_json
- missing_fields

### 5.3 数据保存建议

第一阶段不新增复杂数据表，先复用现有采集体系：

```text
OzonSource.platform = "ozon_product"
OzonSource.capture_method = "ozon_url"
OzonSource.raw_json = 完整采集结果
```

SKU 保存到：

```text
OzonSourceSku
```

图片保存到：

```text
OzonSourceMedia
```

图片需要标记为参考图，不默认作为可发布图片：

```text
media_source = "ozon_reference"
```

### 5.4 跟卖可行性判断

采集后系统应输出：

```text
可参考建品
谨慎跟卖
不建议跟卖
```

判断依据：

- 是否品牌商品
- 是否存在明显商标或 Logo
- 是否疑似专利 / 认证商品
- 是否有高侵权风险图片
- 我方是否有匹配货源
- SKU 是否可复刻
- 价格是否有利润空间
- 类目属性是否能完整匹配

## 7. 商品分析报告

商品分析报告用于判断商品是否值得做，以及后续如何生图、写文案、定价。

建议分析维度：

1. 产品结构分析  
   产品由哪些部分组成，材质、工艺、配件是什么。

2. 核心功能分析  
   产品解决什么问题，用户为什么需要它。

3. 用户体验分析  
   是否易用，是否有情绪价值、身份价值、便利价值。

4. 目标人群分析  
   谁买，谁用，购买动机是什么。

5. 市场竞争分析  
   同类商品多不多，我们的优势、劣势、机会和风险是什么。

6. 定价分析  
   采购价、竞品价、利润空间、目标市场消费层级。

7. 上架建议  
   是否值得做，优先级多少，主图怎么做，详情图怎么做，关键词怎么布局。

## 8. AI 生图工作流

AI 生图不是直接生成图片，而是先生成图片任务。

### 8.1 主图任务

目标：吸引点击。

需要输入：

- 产品主体
- 目标人群
- 核心卖点
- 价格定位
- 使用场景
- 禁止改变的产品结构
- 产品母图
- 参考图

### 8.2 SKU 图任务

目标：让客户分清变体。

需要输入：

- SKU 名称
- SKU 差异
- 颜色 / 版本 / 套装
- 对应产品图
- 统一视觉风格

### 8.3 详情图任务

目标：促成下单。

需要输入：

- 参数
- 功能
- 使用场景
- 包装清单
- 尺寸
- 对比优势
- 使用步骤

## 9. 开发优先级

### P0：采集成果确认

目标：先知道系统采集到了什么，缺什么。

开发内容：

- 采集完整度评分
- 标题 / SKU / 价格 / 图片 / 属性 / 描述完整性检查
- 缺失字段提示
- 采集质量状态

### P1：商品事实档案

目标：形成可信商品资料。

开发内容：

- 合并标题、SKU、图片识别、文本识别、人工确认
- 按通用商品结构归类
- 显示证据来源和置信度
- 支持确认 / 拒绝 / 修正

### P2：OZON 商品链接采集

目标：实现类似 ERP 的单链接采集。

开发内容：

- 新增 OZON 链接采集入口
- 保存为 `platform = ozon_product`
- 提取标题、价格、SKU、图片、属性、描述
- 采集图片默认标记为参考图

### P3：OZON 参考建品 / 跟卖建品

目标：通过 OZON 链接快速生成我方草稿。

开发内容：

- 匹配我方商品 / 货源
- 判断跟卖可行性
- 生成草稿
- 风控提示

### P4：AI 生图工作流

目标：基于事实和分析生成主图、SKU 图、详情图。

开发内容：

- 图片任务生成
- prompt 模板
- 产品母图引用
- 候选图审核

### P5：Listing 草稿与发布闭环

目标：完成审核、校验、发布、失败回流。

开发内容：

- 草稿审核
- 发布前校验
- 提交 OZON API
- 失败原因记录
- 可重试修正

## 11. 最终判断

当前系统最应该走的方向是：

```text
货源建品
+
OZON 参考建品 / 跟卖建品
+
AI 生图与 Listing 自动化
```

这会比单纯做“自动发布”更有价值。

因为它不仅能上架，还能帮助判断：

- 这个商品值不值得做
- 市场上怎么卖
- 我方怎么差异化
- 图片怎么设计
- 标题怎么写
- 价格怎么定
- 上架前有哪些风险

也就是从“工具”升级为“经营辅助系统”。
