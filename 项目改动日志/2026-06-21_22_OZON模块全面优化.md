# OZON 模块全面优化 — 2026-06-21 ~ 06-22

## 一、AI 内容生成（加工页）

### P0-1: MOCK → 真实 API
- `blueprints/ozon.py` → `processing_generate()` 重写
- 从 `UserApiKey` 获取 DeepSeek API Key
- 收集源商品全部数据（标题/类目/描述/SKU/店铺）
- 查询本地 OZON 类目树作为参考
- 调用 `deepseek-chat` 生成：俄语标题、卖点、描述、建议类目路径、置信度
- 未配置 Key 时提示去平台接口页配置

### P0-2: Prompt 优化（参考 OZON Global Help 官方文档）
- 新增 System Prompt：OZON 平台规则、内容评级体系
- 标题模板：`Тип + Бренд + Ключевая характеристика + Назначение`
- 卖点分层：核心功能 → 材质品质 → 使用场景
- 描述结构：概述 → 规格 → 功能 → 场景 → 包装
- 禁止词扩展至 18 个（最高级/营销/平台名）
- 类目提示使用中俄双语路径
- JSON 解析失败自动重试 1 次

### 模板优化
- `processing.html`：类目选择从 `<select>` 改为 `<input> + <datalist>` 可搜索下拉
- 增加 AI 置信度徽标

## 三、类目属性字典 — 数据修复

### 根因：2 张表存在过时唯一索引

| 表 | 过时索引 | 影响 |
|----|---------|------|
| `ozoncategoryattribute` | `(user_id, ozon_category_id, attribute_id)` 不含 `type_id` | 同 dcid 下第二个 type 起属性全部被拦截 |
| `ozonattributevalue` | `(user_id, attribute_id, value_id)` 不含 `type_id` | 同 attribute_id 不同 type 的字典值被拦截 |

### 修复
1. DROP 两个过时索引
2. 修复 `api_sync_current_type_full`：从 `OzonCategoryType` 取 `actual_dcid`，统一写入/查询来源
3. 批量补齐属性 Schema：4,482 个 type，零失败
4. 批量补齐字典值：6,239 个 type，1,217,554 条，零失败
