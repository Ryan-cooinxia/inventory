# 2026-06-28 OZON 视频采集 — webRequest 网络监听增强

## 第一次改动（四级策略 + webRequest 基础）

四级策略（DOM → 点击嗅探 → React → 兜底）能识别视频入口和封面，但 OZON 播放器播放时真实视频 URL 不暴露在 DOM / React 里，新增 webRequest 作为第三级策略。

## 第二次改动（扩展失效保护 + DASH/HLS 识别 + 视频分级）

### 问题 1: Extension context invalidated
- 扩展重载后旧页面 content script 失效 → 所有按钮返回 Extension context invalidated
- **修复**: `sendExtMessage()` 增加 try/catch + chrome.runtime.lastError 检测
- 收到此错误时提示用户刷新页面（Ctrl+F5）

### 问题 2: 视频监听规则太窄
- 之前只匹配 `.mp4/.m3u8/video/stream/player`
- OZON 主视频实际可能使用 DASH/HLS 分段流：`.m4s/.mpd/dash/hls/manifest/init.mp4`
- **修复**: 扩大 `isOzonVideoRequestUrl()` 和 `captureMainVideoByNetwork()` 匹配规则

### 问题 3: 视频分级
- 新增三级分类：`direct` (.mp4/.webm/.mov) > `manifest` (.m3u8/.mpd/dash/hls) > `segment` (.m4s/.ts/init.mp4)
- 只抓到分片时不保存为正式视频，提示用户保持播放更久

## 第三次改动（猫抓式常驻缓存 + PDP 视频精准识别）

### 问题发现
通过猫抓插件验证，OZON 主图视频真实 URL 格式为：
```
https://v-1.ozone.ru/vod/video-69/.../asset_1_h264.mp4?type=pdp
```
域名 `v-{数字}.ozone.ru`，路径 `/vod/video-{数字}/`，参数 `type=pdp`（Product Detail Page）。

### 根因
猫抓能抓到是因为**长期监听全浏览器网络请求**；我们的插件之前是"点击后才开始监听 5 秒"，此时视频可能早已加载完成。

### 架构变更

**新增双重缓存架构：**

```
webRequest.onBeforeRequest 触发
  ├─ 第0层: rememberOzonVideoRequest() — 猫抓式常驻缓存（永久运行）
  │    └─ ozonRecentVideoRequestsByTab[tabId] — 最多 30 条/标签页
  └─ 第1层: session.requests — 用户点击采集后的精确捕获
       └─ ozonVideoCaptureSessions[tabId] — 最多 500 条/标签页
```

**采集流程变为 5 步：**
```
🎬 采集视频
  ├─ 0/5 缓存预取: getRecentOzonVideoRequests() — 读常驻缓存（页载即监听）
  ├─ 1/5 DOM: extractCurrentMainGalleryVideoDom()
  ├─ 2/5 点击嗅探: captureMainGalleryVideoByClick()
  ├─ 3/5 网络监听: captureMainVideoByNetwork() — 不再 start/stop，只读缓存 + 触发播放
  └─ 4/5 React Fiber: probeMainGalleryVideoFromReact()
```

### 关键新增

| 改动 | 文件 | 说明 |
|------|------|------|
| `ozonRecentVideoRequestsByTab` | background.js | 猫抓式独立持久缓存 |
| `isHighConfidenceOzonPdpVideoUrl()` | background.js + content.js | v-*.ozone.ru/vod/...asset_*_h264.mp4?type=pdp |
| `isLikelyOzonPdpVideo()` | background.js | 视频候选判定（不含 /s3/video- 买家秀） |
| `rememberOzonVideoRequest()` | background.js | 常驻缓存写入（去重 + 限 30 条） |

| `getRecentOzonVideoRequestsFromBackground()` | content.js | 读取常驻缓存 |
| `isHighConfidenceOzonPdpVideoUrl()` | content.js | 前端同款高置信判定 |

## 第五次改动（一键自动采集 — 展开→播放→监听→读取）

### 需求
OZON 主视频真实 URL 只有播放器初始化后才请求。之前的流程需要用户手动展开 +1 видео → 播放 → 再点采集，太繁琐。

### 关键认知
**用户点「一键采集入库」或「采集视频」= 用户交互**，浏览器允许在该事件链路中自动播放。利用这个窗口，系统可以自动化完整流程。

### 新增函数

| 函数 | 说明 |
|------|------|
| `findOzonMainVideoEntry()` | 定位 "+\d+ видео" 按钮（左侧缩略图区，排除买家秀） |
| `autoOpenOzonMainVideoPlayer()` | 点击入口 → 等弹窗 → play video → 兜底点播放按钮 |
| `isOzonPdpMp4(url)` | 精确定位 `v-*.ozone.ru/vod/...asset_*_h264.mp4?type=pdp` |
| `getCapturedOzonPdpVideos()` | 从常驻缓存过滤出 PDP mp4 |
| `autoCaptureOzonMainVideoOneClick()` | 编排全流程：确保监听 → 展开播放 → 等6秒 → 读缓存 |

### 一键采集入库接入

`submitCollect()` 中 OZON 页面判断：
- 如果还没有真实 PDP mp4 → 先调 `autoCaptureOzonMainVideoOneClick()`
- 失败不阻塞提交

### 完整流程

```text
用户点「一键采集入库」
  → submitCollect()
    → 检测: OZON 页面 + 无 PDP mp4
    → autoCaptureOzonMainVideoOneClick()
      → startOzonVideoNetworkCapture（确保监听）
      → findOzonMainVideoEntry() → 找到 "+1 видео"
      → 点击入口 → 等弹窗 → play video
      → 等 6 秒（视频请求充分发出）
      → getCapturedOzonPdpVideos() → 读缓存
      → 保存到 window.__ozonExtractedData
    → 继续提交（payload 含视频）
```
