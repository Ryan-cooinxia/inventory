## 1. 背景

当前系统已经具备库存、商品、供应商、采购、销售、汇率、AI 导入等基础能力。下一阶段希望增加 OZON 商品运营能力，让系统可以从国内货源平台采集商品资料，生成适合 OZON 商品卡的俄语内容、图片方案、SKU 数据、售价和利润估算，并在人工审核后通过 OZON API 发布商品。

该功能第一期定位为”半自动刊登工具”，不是无人值守自动发布系统。

核心设计理念参见以下关联文档：
- `docs/ozon_source_to_listing_adaptation_plan.md` — 源商品到 Listing 适配层方案
- `docs/ozon_category_attribute_acquisition_plan.md` — 类目属性字典与字段缺口检查
- `docs/ozon_vision_tool_model_plan.md` — 图片识别工具模型接入方案

## 2. 产品目标

建设一个 OZON 商品刊登工作流：

```text
商品采集 -> 商品事实库 -> 商品适配 -> AI 加工 -> OZON 刊登草稿 -> 成本售价测算 -> 人工审核 -> API 发布 -> 状态回写
```

核心原则：
- **源数据只作为证据，不直接发布**：国内源商品页面采集的数据不能直接作为 OZON Listing 使用。
- **商品事实优先于 AI 文案**：先确认商品事实（是什么、有哪些 SKU、差异、包装、功能），再生成 OZON 内容。
- **支持非一对一适配**：一个源商品可拆成多个 OZON 商品，多个源商品可组合成一个 OZON 套装。

核心目标：

- 支持 1688、淘宝、天猫、拼多多等来源商品资料采集。
- 支持 3C、无人机图传配件、摄影配件、车载工具等主营品类。
- 支持根据源数据生成俄语标题、卖点、描述、类目属性候选。
- 支持生成主图、SKU 图、详情图的图片方案和提示词。
- 支持初版成本、售价、利润估算，并允许人工修改。
- 支持 OZON 测试店发布，后续支持正式店和本土店。
- 所有发布内容必须人工审核后才能提交 OZON。

## 3. 非目标

第一期不做以下内容：

- 不做无人审核自动发布。
- 不做完整广告投放和自动调价。
- 不做完整订单履约。
- 不做复杂竞品跟价。
- 不自动编造认证、品牌授权、保修、产地、尺寸、材质、功能或适配车型。
- 不自动覆盖用户已经人工确认的关键字段。

## 4. 用户角色

### 4.1 运营人员

负责采集商品、审核 AI 生成内容、修改价格和图片、确认发布。

### 4.2 管理员

负责配置 OZON 店铺接口、模型接口、提示词模板、定价规则和类目映射。

### 4.3 系统

负责保存采集资料、生成草稿、执行校验、调用 OZON API、记录发布结果。

## 5. 核心流程

### 5.1 商品采集流程

1. 用户在 1688、淘宝、天猫、拼多多页面使用浏览器插件采集商品。
2. 插件提交商品标题、链接、SKU、图片、规格参数、价格、供应商信息、页面证据。
3. 系统保存为采集商品资料。
4. 用户在采集列表中检查资料完整性。

### 5.2 商品事实提取流程

1. 用户从采集列表选择一个或多个源商品，进入商品适配工作台。
2. 系统提取源商品中的结构化事实字段：
   - 标准商品名、商品类型
   - SKU 颜色、尺寸、款式、套装数量
   - 包装内容、材质、功能、适配型号
   - 尺寸、重量
3. 视觉工具模型（Vision Tool Model）对采集图片执行 OCR 和主体识别，输出结构化视觉事实 JSON。
4. DeepSeek 主模型基于源文本 + 视觉事实 JSON 综合推理，补充商品事实。
5. 所有事实字段标注：置信度、证据来源（源页面 / 图片 OCR / AI 推测）。
6. 不确定字段标记为 `unknown` 或 `pending_confirmation`，不硬填。
7. 用户人工确认或修正事实字段。

### 5.3 商品适配流程

1. 用户确认适配关系：一对一 / 一对多 / 多对一。
2. 系统根据已确认的商品事实，推荐 OZON 类目（通过类目属性字典匹配）。
3. 系统读取该类目的必填属性，执行字段缺口检查（Field Gap Check）。
4. 缺失必填字段时阻断发布，提示用户补充。
5. 用户映射本地事实字段到 OZON 属性字段。
6. 适配完成后生成 OZON 刊登草稿。

### 5.4 商品加工流程

1. 系统保持源 SKU 顺序。
2. DeepSeek 主模型基于已确认的商品事实（非原始源数据）生成俄语标题、卖点、描述、属性候选。
3. 低置信度字段标记为待确认。
4. 不确定字段留空，不允许为了完整度硬填。
5. AI 不得覆盖人工已确认字段。

### 5.5 图片生成流程

1. 视觉工具模型先对源图执行合规检查：是否含中文、水印、二维码、价格、平台 Logo。
2. 系统根据商品品类生成图片槽位：
   - 主图
   - SKU 图
   - 场景图
   - 卖点图
   - 功能图
   - 细节图
   - 尺寸图
   - 包装清单图
2. 用户选择视觉风格。
3. 系统生成图片提示词。
4. 图片模型执行后返回候选图。
5. 用户人工审核图片是否符合 OZON 规则。
6. 审核通过图片才允许进入发布数据。

### 5.6 定价流程

1. 系统读取采购价、汇率、物流估算、佣金估算、广告预留、目标利润率。
2. 生成建议 RUB 售价。
3. 用户可手动修改。
4. 未人工确认价格时，不允许发布。

初版公式：

```text
price_rub = (cost_cny + domestic_shipping_cny + packaging_cny + international_shipping_cny + risk_buffer_cny)
            * cny_to_rub_rate
            / (1 - commission_rate - ad_reserve_rate - target_margin_rate)
```

### 5.7 审核与发布流程

1. 用户进入刊登草稿。
2. 系统执行发布前校验。
3. 有阻断错误时，不能审核通过。
4. 校验通过后，用户点击人工审核通过。
5. 用户选择测试店发布。
6. 系统调用 OZON API。
7. 发布结果写回本地，包括 OZON 商品 ID、offer_id、任务状态、失败原因。

## 8. 业务规则

### 8.1 OZON 上架总原则

- 所有买家可见标题、卖点、图片文字、标签、属性值默认使用自然俄语。
- 只能基于采集数据、图片证据、SKU 信息和 OZON 类目字段生成内容。
- 不能编造认证、品牌授权、保修、产地、尺寸、材质、功能或适配车型。
- SKU 顺序必须与源商品一致。
- 不确定信息写成待确认或留空。
- 避免中文电商话术、夸张承诺、价格促销、平台外导流和侵权品牌词。

### 8.2 SKU 主图规则

- 默认 3:4 竖版。
- 白底或浅色干净背景。
- 主体清晰居中。
- 商品颜色、款式、材质、配件必须与参考 SKU 一致。
- 可见俄语文案只保留简短标题、SKU 规格、2-3 个真实卖点。
- 不放价格、折扣、评分、销量、平台 Logo。

### 8.3 详情图规则

- 默认 3:4 竖版。
- 俄语文字要少、清楚、可读。
- 优先覆盖使用场景、材质细节、核心功能、尺寸参数、适用对象、包装清单、购买理由。
- 参数只能来自源图或源数据。
- 不能出现二维码、联系方式、源平台水印、厂家招商、批发价、国内平台促销。

### 8.4 图片负面规则

禁止：

- 改变颜色、材质、形状、尺寸、配件数量、包装内容和 SKU 款式。
- 新增品牌 Logo、认证图标、保修承诺、专利声明、官方授权。
- 出现 OZON、Wildberries、Yandex、淘宝、天猫、1688、拼多多等平台标识。
- 出现价格、折扣、评分、销量、优惠券、二维码、联系方式。
- 出现中文、英文大段文字、伪俄文、乱码、不可读小字。

### 8.5 质量验收规则

发布前必须核对：

- 商品是否和源图一致。
- SKU 是否对应。
- 俄语是否自然。
- 类目属性是否有依据。
- 图片是否适合 OZON。
- 价格是否人工确认。

如果模型结果与事实冲突，必须回退到源数据。

## 9. 状态流转

### 9.1 采集商品状态

```text
collected -> parsed -> drafted -> archived
```

### 9.2 刊登草稿状态

```text
draft -> needs_review -> ready -> approved -> publishing -> published
                                      \-> failed
```

### 9.3 图片状态

```text
source -> planned -> generated -> reviewed -> approved
                                \-> rejected
```

## 10. 发布前阻断项

以下情况不能发布：

- 未选择 OZON 店铺。
- 未填写俄语标题。
- 未填写 OZON 类目 ID。
- 缺少 SKU 数据。
- SKU 顺序与源商品不一致。
- 类目必填属性未处理。
- 商品事实未人工确认。
- 存在未解决的字段缺口（blocking_gaps）。
- 价格未人工确认。
- 图片未审核通过。
- 主图未经过合规检查。
- SKU 图与 SKU 事实冲突。
- 图片含中文、水印、二维码、价格、平台 Logo。
- 买家可见内容包含禁止词或平台标识。
- AI 生成了无证据的认证、授权、保修、材质、尺寸、适配车型。
